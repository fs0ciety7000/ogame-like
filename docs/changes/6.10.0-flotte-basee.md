# 6.10.0 : Base avancée sur une colonie (Y)

Type : fonctionnalité
Statut : livré (branche `claude/hiver-k-s`)
Proposition : `docs/proposals/flotte-basee.md` (option B, version prudente) ; choix provisoires Q9 et Q10 (`docs/QUESTIONS.md`)

## Demande
Lot Y de la feuille de route : flotte basée sur une colonie (Q.3 de `colonies-suite.md`), décidé le 2026-10-06 ; règle n° 3.

## Diagnostic
Toute flotte partait de la planète mère (`distanceBetween(attacker.uid, cible)`), alors qu'une colonie a ses propres coordonnées.

## Ce qui change
- **Joueur** :
  - Colonies → carte de la colonie → **Base avancée** : « Baser une flotte » (vaisseaux d'attaque, trajet ordinaire), état, décompte, « Lever la base ».
  - Fenêtre d'attaque : choix **Départ** (planète mère ou base) ; les quantités sont celles de la base, le trajet part de la colonie.
  - Après le combat, les survivants reviennent à la base ; le butin arrive à la planète mère.
- **Moteur** (`fleets.ts`) :
  - mission `colonybase`, `COLONY_BASE_RULES` (ouverte, 14 jours, 1 base par colonie), `launchColonyBase` ;
  - `isActiveBase`, `takeFromBase` (I20), `baseReturnUnits` ;
  - `LaunchInput.originId` pour le point de départ ; champ `Fleet.base`.
- **Serveur** (`cosmic_db.js`) :
  - `fleet/send` accepte `mission: "colonybase"` et `fromBaseId` ; la base garde les vaisseaux restants et est levée si elle est vide ;
  - l'arrivée stationne (comme une garnison) ; le retour d'une attaque fusionne les survivants dans la base encore en place.
  - Champ `base` (JSON) ajouté à `fleets` dans `pb_schema.json`.
- **Admin** : Règles → Colonies (ouverture, durée maximale, bases par colonie) ; groupe `colonyBase` du registre.

## Décisions et écarts
- Q9 : la base ne défend pas la colonie et n'est pas attaquable.
- Q10 : 14 jours, 1 base par colonie, retour à la base ou, si la base est levée, à la planète mère.
- Les vaisseaux basés restent comptés dans le hangar de la planète mère et occupent un emplacement de flotte : aucune migration de données.
