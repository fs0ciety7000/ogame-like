# 6.11.1 : La base avancée peut défendre sa colonie (Z4, Q9)

Type : fonctionnalité
Statut : livré (branche `claude/hiver-k-s`), **désactivé par défaut**
Proposition : `docs/proposals/flotte-basee.md` (suite) ; choix noté en Q9

## Demande
Feuille de route de printemps, Z4 : faire combattre la flotte basée quand sa colonie est attaquée.

## Diagnostic
- Le serveur sait déjà faire combattre des garnisons alliées aux côtés d'une planète mère (`garrisons` de `performAttack`, à 50 %), puis leur retirer leurs pertes.
- Pour une colonie, cette liste était vide (`!colonyOwner`).

## Ce qui change
- **Moteur** :
  - `COLONY_BASE_RULES.defendsColony` (faux par défaut) ;
  - `colonyBaseDefends()`, exporté pour le serveur.
- **Serveur** (`resolveAttackArrival`) : quand le réglage est actif, une attaque sur une colonie engage la base avancée de son propriétaire comme une garnison :
  - même facteur de 50 % ;
  - pertes retirées de la fiche de la base ;
  - base levée si elle est vide ;
  - notification « Ta base avancée a combattu ».
- **Admin** : case « Base avancée : défend sa colonie » dans Règles → Colonies.
- **Joueur** : le panneau Base avancée indique si elle défend la colonie.

## Décisions et écarts
- Pas de champ de débris pour un combat sur une colonie (Q13) : la clé du champ (identifiant de la cible) est trop longue pour une colonie. Trouvé par le test d'intégration.
Désactivé par défaut, l'option la plus prudente pour les vaisseaux des joueurs (règle n° 3). Le joueur a créé sa base en lisant « elle ne défend pas la colonie » (6.10.0). L'activer est un choix d'équilibre laissé à l'admin (Q9).

## Invariants et tests
Intégration PocketBase « 6.11.1 base avancée : défend sa colonie quand l'admin l'active » : le rapport de combat compte la base parmi les garnisons, et la base ne gagne jamais de vaisseaux.
