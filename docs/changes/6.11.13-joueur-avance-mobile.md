# 6.11.13 : Pages mobiles mesurées avec un joueur avancé

Type : ajustement
Statut : livré (branche `claude/hiver-k-s`, sans PR : Q12)
Proposition : aucune (lot P1 de `docs/proposals/feuille-de-route-2028-printemps.md`, constat HV-3 d'AU17)

## Demande
Les mesures mobiles portaient toutes sur un joueur neuf. P1 : mesurer avec un joueur avancé, corriger les débordements et les pages
au-dessus de 6 000 px.

## Diagnostic
Variante de `pagelen.mjs` (scratchpad, PocketBase local) : après l'inscription, le profil passe à tous les bâtiments débloqués au
niveau 10, 40 unités de chaque au niveau 5, technos au niveau 5, 250 000 XP. Résultat sur 42 pages à 375 px :
- aucun débordement horizontal, aucune erreur de page ;
- une seule page au-dessus de 6 000 px : Bâtiments **6 460 px** (vingt cartes ouvertes) ; suivent Accueil 5 022, Unités 4 941,
  Missions 4 873 px.
- Sous chaque bâtiment trop cher, l'avertissement tenait sur 3 lignes, alors que la pastille de coût dit déjà « manque 20 k ».

## Ce qui change
- Pour le joueur : l'avertissement sous un bouton grisé tient en une ligne : « Disponible dans ~3 h à production constante. » ou
  « Ta production n'y suffira pas : passe par le marché. » (Bâtiments, Unités, Labo) ; image des bâtiments en 6 rem sur téléphone.
- Pour l'admin : sans objet.
- Dans le code : `afford.tsx` (`affordText`), `BuildingsPage.tsx`.

## Décisions et écarts
- Bâtiments (joueur avancé) : 6 460 → **6 271 px**, encore au-dessus de 6 000 px. Aller plus loin demande de couper les
  descriptions sans moyen de les relire, ou une vue « liste compacte » : choix de conception laissé à l'utilisateur (**Q16**).
