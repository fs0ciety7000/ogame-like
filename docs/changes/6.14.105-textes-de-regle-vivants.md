## Ce qui change
- Pour le joueur : à règles par défaut, les mêmes textes mot pour mot (le test le vérifie), sauf deux textes faux corrigés :
  - Carnet, étape Ascension : « et 3 points de talent » au lieu de « et un point de talent » (une Ascension en donne 3) ;
  - Ordres du jour, expéditions : le nombre suit `expeditionsPerDay` (4 pour la classe Explorateur, 3 sinon).
- Pour l'admin : tout réglage cité ci-dessus se reflète aussitôt dans le texte. Nouveau réglage **Mutateur de saison → force de
  chaque mutateur** (`mutators.values`, une valeur par effet, mêmes défauts), éditable dans Admin → Règles (section Mutateur de
  saison) ; `validateMutatorRules` refuse une valeur hors de 0 à 2 (réduction de durée ou de taxe : 0 à 0,9), un nombre de valeurs
  différent du nombre d'effets, un mutateur inconnu.
- Dans le code :
  - `format.ts` : `formatHours`, `formatPct` (sans Intl, goja) ;
  - fonctions de texte lues à l'usage : `referralWindowText`, `referralGoalLabel`, `bountyRefreshText`, `bountyBoardText`,
    `allianceBossDurationText`, `allianceBossCallText`, `expeditionRelicChanceText`, `mutatorValues` ;
  - `hooksEntry.ts` exporte `allianceBossCallText`, `allianceBossDurationText`, `bountyRank` ;
  - `cosmic_db.js` : `profileGame()` (moteur chargé et règles appliquées une fois par fiche publique), `keshFeats(b, game)`,
    `showcaseOf(player, game)` ; textes d'appel du boss d'alliance lus dans le moteur ;
  - `MUTATORS` : définitions par `mutator(id, nom, emoji, stats, texte)`, `description` et `grants` en accesseurs ;
    `content.ts` fusionne `mutators.values` champ par champ ; `DailyOrder.period` devient `string`.

## Décisions et écarts
- **« 4 contrats toutes les 8 h »** lit `bounties.dailyLimit` (primes par jour), comme l'indiquait l'audit. Le tableau, lui,
  propose 3 contrats (4 au rang qui ouvre l'élite) : le chiffre par défaut est juste dans les deux lectures, mais il ne l'est plus si
  l'admin change `dailyLimit`. Question proposée ci-dessous.
- **Mutateurs** : seulement la **force** (`values`) devient réglable, la liste reste dans le code. La liste complète et les effets
  composés restent au lot AA7 (AA-6), qui reprendra ces valeurs. Une description en accesseur suffit pour que le texte suive.
- Textes **laissés** en dur, et pourquoi :
  - annonces (`Announcement.tsx`) et billets : textes datés d'une mise à jour, ils racontent ce qui a été livré ce jour-là ;
  - formule d'XP des combats (« +40 × rapport de force… ») et passe généré (« +15 % si plus de 40 % ») : chiffres écrits dans
    le **code** (`pvp.ts`, `procedural.ts`), pas dans une règle ; à migrer en règle d'abord (même famille qu'AA3) ;
  - « 40 Ambre (collection de reliques pleine) » (`seasonPass.ts`) : constante du code, même raison ;
  - « Dix empires » (astuce des Seigneurs) : nombre de fiches de contenu, pas une règle ;
  - libellés des succès (« Gagner 500 Ambre ») : le palier fait partie du succès lui-même (contenu, réglable dans l'onglet Succès) ;
  - bornes des messages de validation de l'admin (« entre 1 et 160 h ») : textes d'admin qui citent la borne du code.
- La garde automatique est une **liste connue** (fichier → motif interdit), pas une détection générique : un scan de tous les
  nombres donnerait des centaines de faux positifs (CSS, contenu, commentaires).

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Texte du tableau des primes** : « N contrats toutes les 8 h » lit `dailyLimit` (primes par jour). Faut-il plutôt dire
   « un nouveau tableau toutes les 8 h, N primes par jour » (deux chiffres, chacun juste) ? Choix fait : texte inchangé à règles par
   défaut, lu dans `dailyLimit`. Retour arrière ou changement : `bountyBoardText()` (`bounties.ts`).
2. **Bornes de la force des mutateurs** : 0 à 2 (réduction de durée ou de taxe : 0 à 0,9). Choix fait : larges, comme Q259 ; les
   plafonds de la couche empire (`effectCaps`) s'appliquent de toute façon. Retour arrière : `validateMutatorRules` (`mutators.ts`).
3. **Textes corrigés à règles par défaut** (« 3 points de talent », expéditions de l'Explorateur) : écart volontaire avec la consigne
   « textes identiques », car l'ancien texte était faux. Retour arrière : accesseur `learn` de l'étape `ascend` (`advancedGuide.ts`),
   `dailyOrders.ts`.
