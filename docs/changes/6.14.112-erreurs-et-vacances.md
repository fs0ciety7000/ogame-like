# 6.14.112 : Erreurs traduites et garde de vacances unique (AC-F)

Type : correctif (client, serveur, moteur) + admin + tests
Statut : en cours
Proposition : `docs/proposals/chaine-actions.md` (lot AC-F) ; source : revue AU27, `docs/audit/2026-10-07-au27-chaine-actions.md`
(constats AC-11, AC-16) ; choix validé Q79 (= Q-AC4, option A). Feuille de route `docs/proposals/feuille-de-route-2030-automne.md`,
lot 31.

## Demande
Lot AC-F : « erreurs traduites (403, 409, 429, 503 → messages français clairs côté client) et garde de vacances unique (un seul endroit
vérifie le mode vacances) ».

Vu par le joueur :
- pendant une maintenance, « Améliorer » affichait « Action impossible. » sans dire pourquoi ; une 403 (« Parole retirée », droits
  d'alliance…) remontait brute ;
- en vacances (production gelée, protégé), un joueur pouvait encore toucher son défi, son Codex, jouer au casino, balayer un agresseur
  à la phalange ou passer par la porte de saut : chaque route décidait seule.

## Diagnostic
- AC-16 : `callGame` (`playerService.ts`) ne traduisait que 400 et 404 ; 73 écrans affichent « Action impossible. » pour toute autre
  erreur (`err instanceof GameActionError ? err.message : …`).
- AC-11 : l'action refusait 54 actions sur 62 (`VACATION_ACTIONS`, `actions.ts`) ; `moon/scan`, `fleet/jump`, `bounty`, `casino`,
  `challenge/claim`, `codex/claim`, `pirates`, `rename` et les dépenses d'alliance ne vérifiaient rien ; 7 routes avaient leur propre
  test et leur propre message (`game.onVacation(...)` puis `BadRequestError`).

## Ce qui change
- Pour le joueur :
  - un refus dit toujours **pourquoi**, en français : message du serveur gardé (règle non respectée, droit manquant, conflit,
    maintenance) ; message générique de PocketBase (anglais) ou absent remplacé par un texte clair (« Action refusée : tu n'as pas le
    droit de faire ça. », « L'état a changé entre-temps : recharge la page et réessaie. », « Trop de demandes d'un coup : attends
    quelques secondes et réessaie. », « Le jeu est en maintenance : réessaie à la réouverture. », « Connexion au serveur perdue… ») ;
    une erreur du serveur (500) devient « Erreur du serveur : réessaie dans un instant. L'équipe est prévenue. » et part à l'équipe
    (`reports/error`) ;
  - **vacances** : une seule règle. Rien qui rapporte ou dépense : casino (jeton et tirage), défi, Codex, Comptoir et primes,
    traités et ultimatums, porte de saut, balayage de la phalange, changement de pseudo, dépôt, recherche et projet d'alliance,
    en plus de ce qui était déjà refusé (flottes, marché, enchères, contrats, cadeaux, vendetta, actions). Un message unique :
    « Tu es en vacances : reviens d'abord (Paramètres) pour … » (le geste nommé). Lecture permise (phalange sans balayage, Codex,
    fiches). Les 8 actions permises avant le restent.
- Pour l'admin : réglage **`vacation.allowed`** (Admin → Règles → Mode vacances, « Tous les réglages ») : liste blanche unique, pour
  l'action comme pour les routes (clés : type d'action, `route:geste`, ex. `casino:spin`, `alliance:deposit`, `bounty:shop`).
- Dans le code :
  - `src/lib/gameErrors.ts` (nouveau) : `GAME_ERROR_TEXTS`, `gameErrorText(status, message)`, `isGameMessage`, `isServerFault` ;
  - `callGame` : toute erreur devient une `GameActionError` au message français ; 500 signalée (`reportClientError`) ; requête annulée
    laissée telle quelle ;
  - `src/lib/pocketbase.ts` (`afterSend`) : une erreur d'une route `/api/cosmic/` sans message du jeu reçoit le texte clair, ce qui sert
    aussi les écrans qui appellent `pb.send` directement (casino, primes…) ;
  - `vacation.ts` : `VACATION_RULES.allowed`, `vacationBlock`, `assertNotOnVacation` ; `actions.ts` lit la garde (fin de
    `VACATION_ACTIONS`), `performGift` aussi ;
  - `cosmic_db.js` : `vacationGuard(game, player, now, key)` dans `phalanxScanRequest`, `fleetJumpRequest`, `bountyRequest`,
    `casinoRequest` (tirage), `piratesRequest`, `renameRequest`, `allianceRequest` (dépôt, recherche, projet), et à la place des 7
    tests propres (`tradeContractRequest`, `launchFleetRequest`, `marketCreate`, `marketAccept`, `warlordsRequest`, `auctionRequest` ×2).
    Défi, Codex et jeton du casino passent par l'action en 6.14.113 (même garde) ;
  - `hooksEntry.ts` : `vacationBlock`, `assertNotOnVacation`.

## Décisions et écarts
- **Message du serveur toujours gardé** quand il vient du jeu (français) : on ne remplace que les messages génériques de PocketBase,
  reconnus par leur début (liste fermée dans `gameErrors.ts`).
- **401** traité comme 403 (message clair) ; **404** garde le cas « hooks absents » de 6.14.49.
- **Garde interrogée par geste** : le serveur demande à la garde pour chaque geste qui rapporte ou dépense ; les gestes sociaux
  (alliance : rejoindre, quitter, rangs, profil ; messages ; sondages) restent libres, sans entrer dans la liste.
- **Ultimatum en vacances** : une réponse (payer ou refuser) est refusée ; aucun ultimatum n'est émis pendant les vacances, et partir
  en vacances exige d'y avoir répondu : cas théorique.
- Pas de route `vacation` gardée : on y revient de vacances.

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Gestes sociaux d'alliance en vacances** (rejoindre, quitter, candidatures) : permis. Option : les bloquer aussi. Choix fait :
   permis (ni gain ni dépense, Q79). Retour arrière : appeler la garde pour ces gestes dans `allianceRequest`.
2. **Message d'une 500** : « Erreur du serveur : réessaie dans un instant. L'équipe est prévenue. » (le détail technique part à
   l'équipe, jamais au joueur). Option : montrer le détail aux admins du jeu. Choix fait : même texte pour tous.
3. **Changement de pseudo en vacances** : refusé (il coûte de l'Ambre). Option : le permettre. Choix fait : refusé (« rien qui dépense »).

## Invariants et tests
- Nouvel invariant **I36** (GDD §4) : une seule garde des vacances (`vacationBlock`, liste blanche `vacation.allowed`) pour l'action et
  les routes ; toute route qui rapporte ou dépense l'interroge ; aucune n'a son propre test.
- `src/lib/gameErrors.test.ts` (nouveau) : message du jeu gardé, générique remplacé, 500 signalée, 503 non.
- `src/game/chaineActions.test.ts` (bloc AC-11) : liste par défaut = les 8 actions d'avant, messages par geste, hors vacances rien,
  même liste lue par l'action (réglage ouvert puis refermé).
- `src/server/gardeVacances.test.ts` (nouveau) : chaque route qui rapporte ou dépense passe par `vacationGuard` ; aucune ne teste
  `onVacation` seule.
- Intégration « 6.14.112 (AC-F) » : 403 d'une route du jeu = `GameActionError` au message du serveur ; en vacances : « Tout réclamer »,
  jeton du casino, Codex (catégorie et titre), défi, échange d'Ambre refusés ; `sync` passe ; geste ouvert par l'admin accepté aussitôt.
