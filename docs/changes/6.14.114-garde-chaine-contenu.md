# 6.14.114 : Garde de la chaîne de contenu renforcée et panneau « Chaîne de contenu » (AJ27-4)

Type : fonctionnalité (moteur, admin) + tests
Statut : en cours
Proposition : `docs/proposals/chaine-contenu.md` ; source : revue AU27, `docs/audit/2026-10-07-au27-jeu-chaine.md` (constats AJ-1,
AJ-10, et AJ-9 pour le maillon Ctrl+K ; questions QJ1 et QJ2). Feuille de route `docs/proposals/feuille-de-route-2030-automne.md`, lot 35.

## Demande
Lot AJ27-4 : « garde de chaîne renforcée : maillons `achievementOwn`, `carrierOwn`, `palette` ; types `colony`, `talent`, `module`,
`class` ; `KNOWN_GAPS` à jour ; panneau admin « Chaîne de contenu » ». Règle n° 4 de CLAUDE.md : « si on veut ajouter un nouveau
vaisseau, une nouvelle tech, un nouveau bâtiment, tout s'enchaîne ».

Vu par le joueur : construire sa première Étoile noire ne déclenche rien de propre à elle ; la collection paraît générique. Vu par
l'admin : un contenu ajouté dans l'admin (unité, relique, boss) n'est jamais vérifié.

## Diagnostic
- AJ-1 : la garde de 6.14.11 était verte sans qu'aucun contenu ait un succès ou un porteur à lui : les succès sont comptés par type
  (`unitTypesPct` couvre les 24 unités d'un coup) et le porteur d'effet est rempli par les modules de classe.
- AJ-10 : `contentChainReport` n'était lu que par son test ; `CHAIN_KIND_LABELS` et `CHAIN_LINK_LABELS` nulle part.
- AJ-9 : rien ne vérifiait la recherche Ctrl+K.
- AJ-4 : talents, modules, classes d'empire et colonies hors du rapport.

## Ce qui change
- Pour le joueur : rien de visible.
- Pour l'admin : **Admin → Équilibrage → « Chaîne de contenu »** : un onglet par type de contenu (avec le nombre de maillons manquants),
  interrupteur « Seulement les contenus incomplets » (par défaut), pour chaque contenu ses maillons présents (vert) et manquants
  (rouge), le score `présents / attendus`, un lien vers l'onglet du contenu et, pour un succès ou un porteur manquant, vers l'onglet
  Succès ou Reliques. Le contenu ajouté ou modifié dans l'admin y apparaît (registres en vigueur, recalculés à chaque changement).
- Dans le code (`src/game/contentChain.ts`) :
  - maillons **`achievementOwn`** (unités et bâtiments, QJ1 : une mesure qui ne compte que ce contenu, `chainOwnMetrics()` : sonde →
    espionnages, drone de recyclage → débris recyclés, Atelier → unités réparées, Cale sèche → cale pleine et démantèlements ; identifiants
    lus à l'usage), **`carrierOwn`** (unités : un porteur dont la cible est `unit:<id>` ; une classe ou une catégorie ne suffit pas),
    **`palette`** (`PALETTE_KINDS` : unités, bâtiments, technos ; un test vérifie que `CommandPalette.tsx` lit bien leur registre) ;
  - types **`colony`** (4 biomes, 4 spécialisations), **`talent`**, **`module`** (7 modèles), **`class`** (3 classes d'empire) ;
  - porteurs : les effets ciblés des classes d'empire comptent aussi ;
  - `CHAIN_KIND_ADMIN_TAB`, `CHAIN_LINK_ADMIN_TAB` (liens du panneau), `chainRowScore` ;
  - `src/pages/admin/ContentChainSection.tsx`, monté dans `BalancePanel.tsx`.

## Décisions et écarts
- **QJ1** (succès propre exigé ?) : oui pour les **unités et bâtiments** seulement ; technos, reliques, boss, colonies, talents, modules et
  classes gardent la mesure de type (trop de contenus, collection déjà couverte). Les manques sont listés unité par unité et comblés par
  AJ27-6 (succès dérivés « 100 × », « niveau max », « niveau 20 »).
- **QJ2** (porteur propre par unité) : maillon exigé pour les unités, comblé par AJ27-10 (plans de module « signature » ou reliques) ;
  la Sentinelle l'a déjà (Sceau des Sentinelles).
- **`KNOWN_GAPS`** : 22 succès propres d'unités, 11 de bâtiments, 23 porteurs propres d'unités, Ctrl+K de 8 types (`*`), Codex et
  succès des talents, modules et classes (`*`). Chacun cite son lot (AJ27-6, AJ27-8, AJ27-9, AJ27-10) ; un test l'exige.
- **Codex des talents, modules et classes** : manque connu (AJ27-9, Doctrines et Arsenal), pas dans ce lot.
- **Écart** : le panneau ne vérifie que les maillons calculables dans le moteur ; image, défi, butin, changelog restent dans la fiche du lot.

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Portée du succès propre (QJ1)** : unités et bâtiments seulement. Option : aussi technos et reliques (56 succès de plus). Choix fait :
   unités et bâtiments, comme la recommandation de l'audit ; revenir en arrière : ajouter le type à `OWN_ACHIEVEMENT_KINDS`.
2. **Porteur propre par unité (QJ2)** : exigé (manques notés pour AJ27-10). Option : se contenter des porteurs de classe. Choix fait :
   exigé ; revenir en arrière : retirer `carrierOwn` du rapport.
3. **Panneau** : dans Admin → Équilibrage (diagnostic du contenu). Option : un onglet à part. Choix fait : Équilibrage, à côté de
   l'audit des unités.

## Invariants et tests
- Aucun invariant du GDD touché (la garde est un outil, pas une règle de jeu).
- `src/game/contentChain.test.ts` : couverture des 11 types ; unité ajoutée sans préréglage, succès ni porteur propres → 3 manques ;
  porteur de classe ≠ porteur propre ; relique ajoutée (comme dans l'admin) → dans le bilan et comble le porteur propre de son unité ;
  succès propre seulement pour unités et bâtiments ; chaque type `PALETTE_KINDS` lu par la palette ; libellés ; panneau monté ;
  chaque manque connu cite son lot.

## Design (DESIGN.md)
`Card`, `HudChip` (`asChild` + `button` pour les onglets et les manques cliquables), `HudTag` (maillons : `mint` présent, `danger`
manquant), `HudSwitch`, `EmptyState` (« Chaîne complète »). Nombres en `font-mono tabular-nums`. Pas de tableau large : une ligne par
contenu, maillons en pastilles qui passent à la ligne ; nom et identifiant tronqués. Vérification à 375 px : voir Validation.
