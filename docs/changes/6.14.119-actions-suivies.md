# 6.14.119 : Registre des actions suivies : lune, colonies et contenus dans les objectifs générés (AP-L7)

Type : fonctionnalité (moteur, admin, interface) + tests
Statut : en cours
Proposition : aucune proposition dédiée : recommandation de l'audit `docs/audit/2026-10-07-au27-procedural.md` (constat AP-10, lot
AP-L7) et de `docs/proposals/generation-passe-chroniques.md` (§5.4 : « prérequis étendus à tous les objectifs suivis, poids par
type »). Feuille de route `docs/proposals/feuille-de-route-2030-automne.md`, lot 40.

## Demande
Lot AP-L7 : « Nouveau générateur : registre des actions suivies (lune, colonies, nouvelles unités dans les objectifs) ». Un registre
unique des actions mesurables que les générateurs (passe, Chroniques, défis, objectifs du jour) tirent, au lieu de listes en dur ; y
entrent la lune, la phalange, la porte de saut, les colonies (convois, base avancée, spécialisation) et les nouvelles unités ; chaque
entrée déclare la page qu'elle demande (jamais une page fermée, I31) et son poids réglable. À règles par défaut, les mois déjà générés
ne changent pas ; les nouveaux mois peuvent tirer les nouvelles actions.

Vu par le joueur : la lune, la phalange, la porte de saut et les colonies n'apparaissent jamais dans les Chroniques, le passe, la saga
ni les objectifs du jour ; une nouvelle unité n'entre dans aucun objectif. Le contenu procédural ne suit pas ce qui arrive.

## Diagnostic
- Listes fermées : `ChronicleObjective` (9 actions, `chronicles.ts`), `ACTIVITY_KEYS` et `ORDERS`, `ACTIVITY_DEEDS` (`procedural.ts`),
  `OBJECTIVE_LABELS` (`seasonPass.ts`), `OBJECTIVE_PAGES` (`navUnlock.ts`), `BASE_COUNTS`, `challengeWeights` (`passGen.ts`), saga
  (`ACTIVITY_KEYS`), `ContractType` (10 types). Une action nouvelle demandait du code dans 5 fichiers (AP-10).
- Rien ne comptait la lune ni les colonies dans l'activité du mois (`seasonPass.activity`) : seuls des compteurs de succès
  (`phalanxScans`, `gateJumps`, `colonyConvoys`, `colonyBaseTours`).
- Référence avant le lot : 215 tirages enregistrés (45 chapitres, 45 passes, 45 sagas sur 3 profils de serveur et 5 mois, 80 journées
  d'objectifs du jour) avec le générateur d'avant, comparés après le lot (voir Validation).

## Ce qui change
- Pour le joueur :
  - **objectifs du jour** : « Ramener 1 flotte par la porte de saut » (porte ouverte, page Galaxie ouverte) et « Faire arriver
    2 convois de colonie » (une route logistique posée, page Colonies ouverte), poids 0,5 ; un compte sans lune ni route tire comme avant ;
  - **Chroniques, défis du passe, saga** : améliorer sa lune, balayer à la phalange, sauter par la porte, faire arriver des convois,
    tenir une base avancée peuvent être demandés, **seulement si le joueur médian du serveur les pratique** (au moins 0,5 par semaine) :
    sa page lui est donc ouverte ; les archives et les héros du mois citent aussi ces actions ;
  - rien ne change pour un mois déjà écrit, ni pour un brouillon (aucune régénération).
- Pour l'admin :

  - Admin → Générateur, « Ce que le serveur voit » : lignes des nouvelles actions et colonne « Dans les tirages » (oui, oui
    (pratiquée), non (médiane trop basse), non (poids 0)) ;
  - Admin → Règles → Objectifs du jour : poids et quantités des deux nouveaux types ;
  - Admin → Chroniques : un épisode à action par contenu garde son objectif dans la liste.
- Dans le code :
  - `trackedActions.ts` (nouveau, module feuille) : registre `TRACKED_ACTIONS` (libellé, verbe, deux ordres, page, système, passive,
    mesurée, version, objectif du jour), familles `unit:<id>`, `research:<id>`, `building:<id>` (noms par résolveur posé par
    `content.ts`), règles et métadonnées, `trackAction` / `onTrackedAction`, `setActionAvailability` / `actionAvailable`,
    `extraObjectives`, `measuredPlayable`, `objectiveLabel`, `objectivePage` ;
  - `ChronicleObjective` = toute clé du registre ; `OBJECTIVE_LABELS`, `OBJECTIVE_PAGES` construits depuis le registre ; `ORDERS` et
    `ACTIVITY_DEEDS` retirés de `procedural.ts` (textes repris à l'identique dans le registre) ; `BASE_COUNTS` + 6 actions, `baseCount` ;
  - comptage : `markScan` (phalange), `markJump` (porte), `upgradeMoon`, `runColonyRoute` (convoi non vide), `completeFleetReturn`
    (base tenue), `setColonySpec`, `actions.ts` et `buildPlan.ts` (unités, recherches, améliorations lancées : actions par contenu) ;
  - générateurs : `chooseObjectives`, `worldDigest`, `heroLine`, `archivesText` (`procedural.ts`), `objectiveWeight`

  - Serveur (`cosmic_db.js`) inchangé : le moteur empaqueté fait tout (bundle des hooks reconstruit).

## Règles ajoutées (groupe.champ = défaut)
| Réglage | Défaut | Rôle |
|:--|:--|:--|
| `trackedActions.enabled` | vrai | faux : les tirages ignorent les actions 6.14.119 (elles restent comptées) |
| `trackedActions.weights` | 1 par action, `colonySpec` 0 | poids dans les tirages communs, × poids du générateur |
| `trackedActions.familyWeights` | `unit` 0, `research` 0, `building` 0 | familles par contenu hors des tirages communs (AJ27-7) |
| `trackedActions.familyBase` | `unit` 10, `research` 1, `building` 1 | quantité de base d'une semaine |
| `trackedActions.measuredMinWeekly` | 0,5 | médiane minimale d'une action « mesurée » |
| `chapterBaseCounts` | lune 1, phalange 1, porte 2, convois 10, base 1, spécialisation 1 | quantité de base d'une semaine |
| `dailyContracts.weights` | `gate_jump` 0,5, `colony_convoy` 0,5 | objectifs du jour |
| `dailyContracts.targets` | `gate_jump` 1, `colony_convoy` 2 | quantités |

## Comportement à règles par défaut
- Les 9 actions d'avant gardent leur ordre et un poids global 1 ; les nouvelles s'ajoutent **en fin de liste** et ne sont jouables
  qu'avec une médiane mesurée ≥ 0,5 par semaine. Tant qu'aucune n'est pratiquée à ce niveau, le tirage d'un chapitre, d'un passe ou
  d'une saga est celui d'avant, même graine (215 tirages identiques, dont « Le Contre-Chant » de décembre et ses 4 objectifs, gardés
  en test).
- Objectifs du jour : les deux types n'entrent dans la liste qu'avec une porte ouverte ou une route ; un compte sans lune ni route tire
  exactement comme avant (80 journées comparées) ; un compte qui en a peut les tirer dès le jour suivant (le jour en cours n'est
  jamais refait, I31).
- `GENERATOR_VERSION` reste 3 : aucun brouillon ni chapitre écrit n'est régénéré (consigne du lot).

## Décisions et écarts
- **Version du générateur non montée**, alors que la règle de maintenance de la proposition dit qu'une règle qui change ce que reçoit
  le joueur la monte : à activité égale rien ne change, et la consigne du lot est « un mois écrit ne se régénère pas ».
- **Action « mesurée »** : une page du menu progressif s'ouvre par joueur ; un objectif commun (chapitre, passe, saga) vaut pour tous.
  Le registre ne tire donc une action nouvelle que si le joueur médian du serveur la pratique (sa page est ouverte pour lui). Les
  9 actions d'avant gardent leurs seuils propres (I18, I19), pour ne rien changer.
- **Défi hebdomadaire hors du registre** : ses types sont des compteurs de volume (ressources échangées, unités construites) et sa
  rotation est un hachage de la semaine modulo le nombre de types : en ajouter réécrirait tout le calendrier. Reporté (voir Suites).
- **Spécialisation de colonie** : dans le registre, comptée, mais poids 0 (une ou deux fois par colonie, jamais une médiane
  hebdomadaire).
- **Familles par contenu comptées au lancement** (comme les objectifs du jour « Lancer une recherche »…), pas à la fin du chantier ;
  une annulation ne décompte pas. Elles servent l'épisode « nouveauté » (6.14.120) ; leur tirage d'office est AJ27-7.
- **Convoi de colonie** : automatique une fois la route posée, d'où 2 convois demandés (les routes partent toutes les 6 h au plus vite).
- Libellés et ordres des 9 actions repris mot pour mot (aucun texte joueur changé).

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Seuil des actions mesurées** : 0,5 par semaine pour le joueur médian. Option : 0,25 (seuil d'entrée des défis du passe). Choix
   fait : 0,5 (prudent : un objectif commun ne doit pas viser une page fermée à la moitié du serveur). Retour arrière :
   `trackedActions.measuredMinWeekly`.
2. **Objectif du jour « convoi de colonie »** : poids 0,5, 2 convois. Option : poids 0 (objectif presque gratuit pour qui a une route).
   Choix fait : 0,5 (récompense l'usage des routes). Retour arrière : `dailyContracts.weights.colony_convoy`.
3. **Défi hebdomadaire** : hors du registre pour l'instant. Option : types du registre ajoutés à la rotation avec un poids (rotation par
   tirage pondéré au lieu du modulo). Choix fait : reporté à AP-L9 ou AA7 (calendrier inchangé).
4. **Version du générateur** : non montée (consigne). Option : monter à 4 pour régénérer les brouillons et chapitres non commencés.
   Choix fait : non montée ; « Régénérer » dans l'admin applique le registre à un mois non commencé.
