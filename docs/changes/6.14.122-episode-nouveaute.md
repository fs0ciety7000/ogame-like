# 6.14.122 : Épisode « nouveauté » des Chroniques pour un contenu récent (AP-L8)

Type : fonctionnalité (moteur, admin, interface) + tests
Statut : en cours
Proposition : aucune proposition dédiée : recommandation de l'audit `docs/audit/2026-10-07-au27-procedural.md` (constat AP-10, lot
AP-L8 : « un contenu ajouté depuis le mois précédent donne un objectif du chapitre suivant, à partir de la date d'ajout du contenu »).
Feuille de route `docs/proposals/feuille-de-route-2030-automne.md`, lot 41. S'appuie sur 6.14.121 (actions par contenu).

## Demande
Lot AP-L8 : un générateur d'épisode de Chroniques qui met en avant un contenu ajouté récemment (date d'ajout dans le contenu),
réglable (fréquence, durée de « nouveauté »), avec une bibliothèque de textes ; la règle du contenu généré tient (jamais écraser la
configuration, un chapitre manuel passe par `applyLibraryChapter`).

Vu par le joueur : un nouveau vaisseau arrive, mais rien dans le jeu ne le lui présente ; le chapitre du mois suivant parle d'autre chose.

## Diagnostic
Aucune date d'ajout sur les unités, technos et bâtiments (`UnitDef`, `TechDef`, `BuildingDef`) ; les épisodes ne tirent que des
actions génériques (AP-10). L'action par contenu existe depuis 6.14.121 (`unit:<id>` comptée au lancement).

## Ce qui change
- Pour le joueur :
  - un contenu daté depuis **45 jours** au plus au 1er du mois prend l'**épisode 2** du chapitre (ouvert le 8) :
    « Le chantier a un nouveau plan : Récolteur. Construis-en 5. » (5 unités, 1 niveau de recherche ou 1 amélioration) ;
  - seulement si **50 %** des joueurs actifs y ont accès (unité débloquée, techno aux prérequis remplis, bâtiment ouvert) ;
  - l'épisode porte la mention **Nouveauté** (puce violette, date d'ajout au survol) ; « J'y vais » mène à Unités, Labo ou Bâtiments ;
  - un contenu n'est mis en avant qu'une fois ; un mois déjà écrit ne change pas ; la récompense de l'épisode reste celle tirée sous budget.
- Pour l'admin :
  - champ **« Ajouté le »** (AAAA-MM-JJ) dans les fiches Unités, Technologies, Bâtiments ; posé d'office à la date du jour pour un
    contenu créé dans l'admin ; vide = jamais mis en avant ;
  - nouveau groupe **`novelty`** : activer, au plus un épisode tous les N mois, durée de nouveauté, épisode remplacé, quantités par
    famille, familles mises en avant, part d'accès, **bibliothèque de textes** (titres, accroches, ordres par famille) ; section
    **Admin → Règles → « Chroniques : épisode « nouveauté » (6.14.122) »** (dit quel contenu est nouveau pour le mois suivant) ;
  - « Pourquoi ces chiffres » du chapitre : contenu choisi et part d'accès, ou raison de l'absence (fréquence, accès trop faible).
- Dans le code :
  - `novelty.ts` (nouveau) : règles et métadonnées, `recentContent`, `contentToMeasure`, `hasContentAccess`, `chooseNovelty`,
    `noveltyTexts`, `addedOnError`, `validateNoveltyRules` ;
  - `procedural.ts` : `WorldDigest.access` (part des actifs qui ont accès à chaque contenu daté récent), épisode remplacé dans
    `generateChapter` avec sa graine (`novelty:<mois>:<variante>`), `auto.novelty` ;
  - `chronicles.ts` : `ChapterAuto.novelty` ; `units.ts`, `technologies.ts`, `buildings.ts` : `addedOn` ; `content.ts` : validation ;
  - admin : `NoveltyFields.tsx`, `forms.tsx` (« Ajouté le ») ; joueur : `ChronicleTimeline.tsx` (mention « Nouveauté »).
  - Serveur (`cosmic_db.js`) inchangé : la tâche du générateur écrit le chapitre comme avant (`Object.assign({}, content.chronicles,
    { months })`, réglages gardés).

## Règles ajoutées (groupe.champ = défaut)
| Réglage | Défaut | Rôle |
|:--|:--|:--|
| `novelty.enabled` | vrai | épisode « nouveauté » dans les chapitres générés |
| `novelty.everyMonths` | 1 | au plus un épisode tous les N mois |
| `novelty.noveltyDays` | 45 | durée de « nouveauté » (date d'ajout → 1er du mois) |
| `novelty.episode` | 2 | épisode remplacé (1 à 4) |
| `novelty.counts` | `unit` 5, `research` 1, `building` 1 | quantités |
| `novelty.families` | toutes | familles mises en avant |
| `novelty.minAccessShare` | 0,5 | part des actifs qui doivent y avoir accès |
| `novelty.texts` | 6 titres, 4 accroches, 2 ordres par famille | bibliothèque (`{name}`, `{count}`, `{s}`, `{faction}`, `{villain}`) |

## Comportement à règles par défaut
- Aucun contenu par défaut n'a de date d'ajout : **aucun épisode « nouveauté »** tant qu'un contenu daté n'arrive pas (dans le code ou
  l'admin) ; les chapitres sont ceux d'avant (même vérification que 6.14.121, 215 tirages identiques).
- Un contenu daté ne réécrit aucun mois déjà écrit ; seul un chapitre généré ensuite (le 20 du mois d'avant, ou « Régénérer » d'un mois
  non commencé) peut le mettre en avant. Les autres épisodes, le titre, le boss et les récompenses du chapitre sont ceux qu'il aurait eus
  sans nouveauté (graine propre, testé).

## Décisions et écarts
- **Date d'ajout explicite** (`addedOn`) plutôt qu'une détection automatique (premier passage du générateur, mémoire en base) :
  aucun état serveur nouveau ; l'admin la voit et la règle ; posée d'office à la création dans l'admin ; dans le code, une garde de
  comptage (`nouveaute.test.ts` : 67 contenus d'avant sans date, ce nombre ne monte plus) oblige à dater un contenu ajouté.
- **Épisode 2** remplacé (et pas un 5e épisode) : quatre épisodes sont un invariant (I19, `validateChronicles`, calendrier 1/8/15/22).
  Le 2e laisse trois semaines ; le 3e reste le « rebondissement » (Q85).
- **Accès** : sans joueur actif mesuré (serveur neuf), pas de nouveauté (prudent). Fenêtre de mesure de l'accès : contenus datés dans
  les 45 + 92 jours autour de la date de la photographie.
- **Chapitre de la bibliothèque** : `applyLibraryChapter` retire `auto`, donc aucune marque « nouveauté » ; le contenu reste éligible
  le mois suivant (s'il est encore dans sa fenêtre).
- Pas de nouveau succès, Codex ni porteur : l'épisode est un objectif d'un contenu existant (la chaîne du contenu lui-même reste celle
  de son lot).

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Date d'ajout** : explicite (`addedOn`). Option : détection automatique au premier passage du générateur (nouvel état dans
   `procedural`). Choix fait : explicite + garde de comptage. Retour arrière : champ « Ajouté le » vide.
2. **Épisode remplacé** : le 2e. Option : le 3e (rebondissement) ou le 4e. Choix fait : le 2e. Retour arrière : `novelty.episode`.
3. **Contenus déjà en jeu** (vaisseaux de classe, Récolteur, Croiseur de raid…) : non datés, donc jamais mis en avant. Option : les
   dater pour qu'ils aient leur épisode en décembre. Choix fait : non datés (aucun chapitre ne change sans contenu nouveau). Retour
   arrière : « Ajouté le » dans leur fiche (Admin → Unités).
4. **Accès insuffisant** : pas d'épisode. Option : épisode quand même, quantité 1. Choix fait : pas d'épisode (un épisode bloqué
   coûte le chapitre). Retour arrière : `novelty.minAccessShare`.
