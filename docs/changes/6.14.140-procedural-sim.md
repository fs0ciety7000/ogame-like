# 6.14.140 : Outil `procedural-sim.mjs` : simulation des générateurs (AP-L14)

Type : docs (outillage)
Statut : livré (branche de travail)
Proposition : aucune proposition dédiée : lot AP-L14 de l'audit `docs/audit/2026-10-07-au27-procedural.md` (« reprise des
simulations de cette revue, à lancer avant chaque lot qui touche un générateur »). Feuille de route
`docs/proposals/feuille-de-route-2030-automne.md`, lot 56.

## Demande
Lot AP-L14 : outil `scripts/procedural-sim.mjs` dans le dépôt (simulation des générateurs sur N mois : répétitions, variété,
faisabilité), documenté.

## Diagnostic
Les simulations de la revue AU27 (60 mois de Chroniques, 48 mois de passe, 200 serveurs bruités, rotations) étaient des scripts
jetables du scratchpad : chaque lot qui touchait un générateur les réécrivait (6.14.58, 6.14.121, 6.14.125, 6.14.128).

## Ce qui change
- Pour le joueur : sans objet.
- Pour l'équipe : `node scripts/procedural-sim.mjs [--months 24] [--from 2026-11] [--profile reel|typique|vide|bruite|all]
  [--servers 50] [--rules fichier.json] [--base avant-ap|fichier.json] [--json]` :
  - empaquette le moteur (`src/game`) par esbuild, comme `progression-sim.mjs` (rien d'écrit dans le dépôt) ;
  - profils : **réel** (médianes de la pré-prod au 7 octobre 2026, points de passe 63 et 171 par jour), **typique** (serveur calme),
    **vide** (aucune mesure), **bruité** (N serveurs aux médianes du réel × 0,5 à 1,5 ; faisabilité du passe) ;
  - Chroniques enchaînées comme le serveur (chaque mois voit les mois écrits) : factions, titres distincts et première répétition,
    images de boss, répliques et titres d'épisode distincts sur 12 mois, épisodes sur une action de médiane sous le seuil ou nulle ;
  - passe : noms, commandants, paires de rôles distincts, première répétition, répliques des jalons, jour de fin simulé du médian et
    du plus actif, mois où le médian dépasse `passGen.latestMedianDay` ou où le plus actif finit avant `targetTopDay` ;
  - saga : titres répétés deux mois de suite, faction du chapitre ; mutateurs : minimum de distincts sur 12 mois glissants, écart
    minimal entre deux retours ;
  - `--base avant-ap` : côté « avant » aux réglages d'avant AP-L9 à AP-L12 (`mutators.noRepeatMonths` 0, `narrative.enabled` faux,
    `seasonGen.enabled` faux) ; `--rules` / `--base` acceptent un fichier `{ "rules": { … } }`.
- Dans le code : `scripts/procedural-sim.mjs` (nouveau) ; `docs/WORKFLOW.md` §4.1 (à lancer avant et après un lot qui touche un
  générateur).

## Décisions et écarts
- **Pas de garde en test** : l'outil mesure ; les gardes sont dans les tests des lots (`mutators.test.ts`, `varieteNarrative.test.ts`,
  `saisonsGenerees.test.ts`, `defisFaisables.test.ts`).
- **Profil réel figé** (médianes du 7 octobre 2026) : la lecture de la pré-prod reste dans les scripts `preprod-*` ; un profil
  mesuré plus tard se passe par `--rules` ou s'ajoute à `PROFILES`.
- Constats relevés par la première mesure (48 mois), notés pour la suite : saga d'alliance sur une autre faction que le chapitre 46
  mois sur 48, titre de saga répété d'un mois sur l'autre 10 fois sur 48 (AP-6, lot AP-L6, « plus tard ») ; plus actif au dernier
  palier vers le jour 10 à 13 (AP-11) ; profil réel : 30 épisodes sur 192 sur une action de médiane nulle (sondes, marché ; actions
  à la main du joueur, quantité minimale : pas un blocage, voir I19).
