## Demande

Lot R5 (AJ27-11) de la feuille d'hiver 2031 (`docs/proposals/feuille-de-route-2031-hiver.md` §0), partie « exports » : retirer les
exports morts du moteur (15 relevés en AU27, `docs/audit/2026-10-07-au27-jeu-chaine.md`, AJ-14), rendre non exporté ce qui ne sert
que dans son module, un outil réutilisable pour les recenser et une garde qui échoue si un nouvel export mort apparaît. Le retrait des
missions du jour attend la mise en production + 30 jours (hors lot).

Problème joueur : aucun. Bruit dans le code pour les agents et les relecteurs ; un export public laisse croire qu'une fonction sert ailleurs.

## Diagnostic

Recensement refait par `scripts/dead-exports.mjs` (nouveau) sur `src/game` (3 093 exports) et `src/lib` (246) :

- **Morts** (nommés nulle part, pas même dans leur module) : 20 dans `src/game`, 2 dans `src/lib`. Des 15 d'AU27, 12 le sont
  encore : `guideCurrent` est lu par `navUnlock` et les deux `CHAIN_*_LABELS` par l'admin (« Chaîne de contenu », AJ27-4) ; 8 autres
  s'y ajoutent (`memberProjectLevel`, `progressionSummary`, `CHOICE_SLOTS`, `conditionalContractType`, `contractDrawShare`,
  `objectiveSystem`, types `UnitSelector` et `RuleMeta`).
- **Locaux** (valeur exportée lue seulement dans son module) : 153 dans `src/game` (77 modules ; `fleets` 9, `alliances` 7,
  `bounties` 7, `passSeasons` 6…), 11 dans `src/lib`.
- Imports inutilisés laissés dans le moteur (avertissements eslint) : 5.

Méthode : un nom est « lu ailleurs » dès qu'un autre fichier le contient comme identifiant, commentaires retirés. Fichiers lus : tout
`src/` (pages, services, tests, `src/server/hooksEntry.ts`, donc tout ce que `cosmic_db.js` appelle via le bundle), `scripts/`,
`e2e/`, `pocketbase/pb_hooks/` écrits à la main (le bundle généré `cosmic_game.js` est ignoré : il contient tous les noms), fichiers
de configuration de la racine. L'approche est prudente (un nom cité dans une chaîne compte comme lu) : elle peut manquer un mort,
jamais en signaler un vivant à tort, et `tsc` ou eslint arrêtent toute erreur restante.

## Décisions et écarts

- **Missions du jour** : `dailyReadyCount` (`dailyMissions`) est mort mais reste, en exception de la garde : tout le système part
  d'un bloc 30 jours après la mise en production (Z0), consigne du lot.
- **Types** : un type ou une interface lu seulement dans son module reste exporté (il décrit souvent la signature d'une fonction
  publique ; aucun coût à l'exécution). Seuls les types morts sont retirés. La garde suit la même règle.
- Les exports lus **seulement par des tests** (`canJump`, `canScan`, `takeModulePlan`, `computeElapsedProduction`…, cités par AU27)
  restent : un test est un usage (consigne du lot).
- Les exports de `hooksEntry.ts` que `cosmic_db.js` n'appelle pas ne sont pas recensés (hors du périmètre ; idée en Suites).
- `src/lib` est aussi couvert (« si utile » dans la demande) : 2 morts et 11 locaux, même garde.

## Invariants et tests

- Aucun invariant du GDD touché ; aucun comportement ne change (retraits de code non appelé, `export` retiré).
- `src/game/deadExports.test.ts` : lecture des déclarations, listes et types par l'outil ; `src/game` et `src/lib` sans export mort
  ni valeur lue seulement dans son module, hors exceptions (`ALLOWED`, raison obligatoire) ; chaque exception est encore un candidat
  (une exception devenue inutile fait échouer la garde). Le fichier de la garde est ignoré par l'outil (sa liste d'exceptions nomme
  les candidats).
