## Demande
Premiers constats « faisable seul » de l'inventaire : COM-3 (casino et pot absents de la santé), PNJ-5 (unités d'élite), PNJ-4 (raids
repoussés, repaires), PRG-5 (rythme des succès). Sans ces relevés, les mesures attendues après la mise en production n'ont rien à lire.

## Diagnostic
`balance/health.ts` ne lisait ni le casino, ni le pot commun, ni les unités d'élite. Les raids n'apparaissaient que dans l'historique
quotidien, et les succès seulement en médiane.

## Ce qui change
- Pour le joueur : sans objet.
- Pour l'admin : Admin → Équilibrage → Santé gagne quatre tuiles et deux listes :
  - « Raids repoussés (7 j) », avec la cible 60 à 80 % et les repaires pris ;
  - « Unités d'élite », avec la part des joueurs qui en ont débloqué une, puis la liste par type ;
  - « Casino (semaine) » : joueurs qui ont joué, tirages médians, gros lots ;
  - « Pot commun » : valeur et Ambre, puis les entrées par source ;
  - « Succès » montre aussi les points gagnés en 7 jours, d'après l'historique quotidien.
- Dans le code :
  - `npcHealth`, `casinoHealth` (`health.ts`) ;
  - champs `npc`, `elites`, `casino` de `BalanceHealth` ;
  - `achievementsPace` (`history.ts`) ;
  - `liveBalance` (`cosmic_db.js`) passe le pot commun ;
  - bundle des hooks reconstruit.
