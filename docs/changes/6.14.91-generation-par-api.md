# 6.14.91 : génération des illustrations par API (OpenAI gpt-image-1)

Type : ajout (outillage) + docs
Statut : en cours (script prêt ; première génération quand `OPENAI_API_KEY` et l'hôte `api.openai.com` seront disponibles)
Proposition : aucune (outillage du maillon 13 « Illustrations », `docs/illustrations.md`)

## Demande
Décision de l'utilisateur (2026-10-07) : « toutes les illustrations restantes seront générées par une API officielle ». Fournisseur
retenu : OpenAI, modèle `gpt-image-1`. Problème derrière : 89 images attendent un rendu Midjourney fait à la main sur mobile ; les
images provisoires restent en jeu tant qu'elles n'arrivent pas.

## Diagnostic
Sans objet (pur ajout d'outillage). Constats utiles :
- `scripts/illustrations.json` : 129 emplacements, 89 à faire (`done` vide) ; tous les prompts portent `--ar` et `--v`, la plupart
  `--style raw` et `--s` ;
- `scripts/illustrations.py` lit `<dossier>/<id>.(png|jpg|jpeg|webp)` : un rendu écrit `<id>.png` est directement intégrable ;
- avec un rendu déjà transparent (`background: "transparent"`), rembg referait un détourage inutile et pourrait ronger les bords.

## Ce qui change
- Pour le joueur : rien tout de suite (les images arriveront par les lots d'intégration suivants).
- Pour l'admin : sans objet.

  - `scripts/illustrations-api.mjs` : fonctions pures (paramètres Midjourney, conversion du prompt, préfixe de style commun

    journal `journal.jsonl` ; recadrage au `--ar` des emplacements à hauteur libre (bannières 21:9) ; refus sans `OPENAI_API_KEY`
    (clé jamais écrite ni journalisée) ;
  - `scripts/illustrations.py` : détourage sauté si l'image a déjà au moins 2 % de pixels transparents (« fond déjà transparent »).

## Décisions et écarts
- Taille d'API choisie au plus près du `--ar` (écart en logarithme) : 1:1 → `1024x1024` ; 16:9, 16:10, 21:9 → `1536x1024` ; 4:5 →
  `1024x1536`. Le recadrage final reste celui d'`illustrations.py` ; seuls les emplacements à hauteur libre (5 bannières de factions,
  21:9) sont recadrés dès la génération, sinon ils garderaient le 3:2 de l'API.
- Qualité par défaut `medium` (bon compromis prix / détail pour des images affichées de 256 à 1920 px) ; `high` pour les en-têtes et
  annonces si le rendu `medium` déçoit.
- Une image déjà présente dans le dossier de travail est sautée (pas de double paiement) ; `--force` pour la refaire.
- Prompts non réécrits dans `illustrations.json` (lecture seule) : la conversion est faite à la volée, les prompts Midjourney restent
  valables pour un rendu manuel.
