# 6.14.95 : Métadonnées des réglages de l'admin (AA2)

Type : ajout (admin) + test
Statut : en cours
Proposition : aucune (outil d'administration, sans effet sur l'équilibre) ; audit `docs/audit/2026-10-07-au27-admin-evolutif.md`,
constats AA-24 et AA-28, lot AA2 ; feuille de route `docs/proposals/feuille-de-route-2030-automne.md`, lot 21.

## Demande
Lot AA2 de la feuille de route : « Libellés, unités, bornes et aide pour chaque réglage de l'admin ». Problème vu par l'admin :
56 groupes de règles du registre n'avaient aucune section dédiée. Dans « Admin → Règles → Tous les réglages (avancé) », il ne voyait
que des noms techniques (`attackJitterHours`, `scanCostMin`…), sans unité, sans aide, sans bornes, et sans savoir ce qu'il avait
modifié (AA-28 : aucun avant / après, aucun ordre de grandeur).

## Diagnostic
- `AllRulesEditor.tsx` n'avait que 19 libellés (`FIELD_LABELS`), sans groupe : ≈ 9 % des champs du registre décrits.
- `validateRules` ne contrôlait que le type et le signe d'un nombre (et `Pct` ≤ 1) : rien n'empêchait `phalanx.rangePerLevel = 500`
  ou `globalChat.cooldownMs = 0`.
- Les avertissements d'écart ×2 (`ruleDriftWarnings`, 6.14.59) n'apparaissaient qu'en liste en haut de l'onglet, loin du champ.

## Ce qui change
- Pour le joueur : rien.
- Pour l'admin :
  - chaque champ de premier niveau des **71 groupes du registre** (393 champs) a un libellé clair en français, et 317 d'entre eux une
    unité et des bornes ; 19 champs des groupes historiques sont repris de l'ancien dictionnaire ;
  - « Tous les réglages (avancé) » montre, par champ : libellé, nom technique en petit, défaut, bornes, unité (suffixe du champ ; « part »
    affiche aussi le pourcentage), aide ; pastille « modifié » et bouton « Défaut » si la valeur diffère du défaut ; encadré rouge hors
    bornes (enregistrement refusé), encadré orange au-delà de ×2 ou ÷2 du défaut ; compteur de champs modifiés ; interrupteur
    « Seulement les modifiés » ; la recherche lit aussi les libellés et les aides ;
  - `validateRules` (onglet Règles et garde serveur `guardContentConfig`, qui l'appelle par `contentSectionErrors`) refuse une valeur
    hors de `min` / `max`, avec le libellé du champ. Une valeur hors bornes déjà enregistrée ne bloque pas le serveur (seules les
    erreurs nouvelles bloquent, 6.14.59), mais l'onglet Règles demandera de la corriger avant d'enregistrer.
- Dans le code :
  - `src/game/ruleMeta.ts` (nouveau, sans import) : type `RuleFieldMeta { label, unit?, min?, max?, hint? }`, `ruleBoundError`,
    unités (`RULE_UNIT_LABELS`), `HISTORICAL_RULES_META` (groupes de `content.ts` hors registre), `NESTED_FIELD_LABELS` (sous-champs) ;
  - un `X_META` littéral à côté de chaque objet de règles du registre (57 modules de `src/game`) ; `buildingUnlockCostMeta()` dans
    `buildings.ts` (clés dérivées des bâtiments, lues à l'usage) ;
  - `ruleRegistry.ts` : champ `meta` de chaque entrée (accesseur, comme `target`), `ruleGroupMeta`, `ruleFieldMeta` ;
  - `content.ts` : bornes dans `validateRules` ; `AllRulesEditor.tsx` réécrit (composant `RuleField`).
  Aucune valeur par défaut ne change.

## Décisions et écarts
- Métadonnées **à côté de l'objet** (option recommandée d'AA-Q1) ; le registre les relie par accesseur, valeurs littérales (piège
  « Initialisation des modules »). Les groupes historiques, déjà couverts à ≈ 85 % par des sections dédiées, ont une table dans
  `ruleMeta.ts` plutôt que des `_META` éparpillés dans `content.ts`.
- Le contrôle de forme des clés se fait par le test (et non par le type) : un `_META` déclaré hors du registre n'a pas besoin
  d'importer de type, ce qui évite tout import nouveau dans les modules du moteur.
- Bornes larges et prudentes : chaque défaut **et chaque valeur visée par la bascule du rythme** (recherche ×25, Ascensions 10,
  comptoir 0,004, lune) est dans ses bornes ; le test le vérifie. Les objets imbriqués et listes (paliers, coûts, `vendetta`…) ont un
  libellé et une aide mais pas de bornes (leur forme est vérifiée par AA1).
- La première intégration a montré deux bornes trop serrées pour des réglages d'essai légitimes (refus par la garde serveur, preuve
  que le garde-fou fonctionne) : `moon.debrisPerPercent = 10` (lune certaine) et `phalanx.rangePerLevel = 200` (toute la carte).
  Bornes élargies (`debrisPerPercent` ≥ 1, `rangePerLevel` ≤ 200) plutôt que changer les tests.
- `territories.cols` / `rows` : bornes égales au défaut (6 et 4), cohérentes avec le refus existant (grille figée).
- `buildingUnlockCost` : métadonnées générées depuis la liste des bâtiments (clés dynamiques), avec une aide qui renvoie à l'onglet
  Bâtiments.
- Bouton « Défaut » sans confirmation : rien n'est enregistré avant le bouton d'enregistrement de l'onglet.

### Questions proposées (à reporter dans `QUESTIONS.md`)
1. **Bornes des réglages** : bornes choisies larges (souvent 0 à ≈ 10 × le défaut). Faut-il des bornes plus serrées pour les chiffres
   d'équilibre (Ascension, primes, seigneurs) ? Choix fait : larges, pour ne bloquer aucun réglage existant en production (non vérifié :
   la production reste en lecture seule). Retour arrière : modifier `min` / `max` du `_META` concerné.
2. **Bornes croisées** (min ≤ max : `travelMinHours` ≤ `travelMaxHours`, `nameMin` ≤ `nameMax`, `shieldPct` < `ripostePct`…) : non
   vérifiées dans ce lot. Proposition : les ajouter à AA1-suite ou à AA3.

### Ligne proposée pour CLAUDE.md (non modifié, à reporter par la session)
Dans « Règles du moteur », après le registre : « Un nouveau champ d'un objet de règles du registre reçoit son entrée dans le
`X_RULES_META` voisin (`{ label, unit?, min?, max?, hint? }`, valeurs littérales) : `ruleRegistry.test.ts` échoue sans libellé ou si le
défaut sort de ses bornes, et `validateRules` refuse une valeur hors bornes. »

## Invariants et tests
- `ruleRegistry.test.ts` : trois tests ajoutés. (1) Chaque champ de chaque groupe du registre a un libellé, et chaque métadonnée vise
  un champ existant. (2) Métadonnées JSON pures, `min` ≤ `max`, bornes seulement sur des nombres, chaque défaut dans ses bornes
  (registre et groupes historiques), `validateRules` vide sur les défauts **et après la bascule du rythme**. (3) Une valeur hors bornes
  est refusée avec son libellé (`phalanx.rangePerLevel = 500`, `fleets.mapSize = 5`). Aucune liste d'exceptions.
- Aucun invariant du GDD ne change (outil d'admin).
