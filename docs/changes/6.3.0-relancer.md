# 6.3.0 : Relancer toutes les missions

Type : ajout (QoL)
Statut : livré (branche `claude/hiver-k-s`)
Proposition : `docs/proposals/flottes-emplacements.md` (suite H) ; lot O de `docs/proposals/feuille-de-route-2026-hiver.md`

## Demande
> « continue le plan … on code on build, on ajustera sur le long terme »

## Diagnostic
« Relancer » (5.33) ne gardait que les départs passés par `sendFleet` (attaques, raids, missions ciblées). Les primes, la proie d'élite, les
trois boss, les transports de colonie et les livraisons de contrats appelaient `fleet/send` directement : rien à relancer.

## Ce qui change
- Joueur : « Relancer » dans le panneau Flottes renvoie la dernière mission, quelle qu'elle soit (attaque, prime, proie d'élite, boss mondial,
  boss de saison, boss d'alliance, transport, livraison), avec la même flotte et les mêmes options. Le serveur revérifie tout : une prime
  déjà remplie ou un boss en recharge est refusé avec son message habituel.
- Code : `launchFleet(body, cible)` (`playerService.ts`) remplace les appels directs à `fleet/send` (`bountyService`, `leviathanService`,
  `seasonBossService`, `AllianceBossTab`, `tradeContractService`, `sendTransport`) ; `lastMissionStore.ts` garde le corps de la requête
  (`parseLastMission` lit aussi l'ancienne forme 5.33).

## Décisions et écarts
- « Relancer à l'identique depuis un rapport » existe déjà (« Réattaquer avec la même flotte », 5.23) : rien à ajouter.
- Emplacements à débloquer : pas encore, en attente des relevés (santé de l'équilibre, lot K) sur l'usage des 10 emplacements.
- Aucune règle serveur ne change.

## Invariants et tests
