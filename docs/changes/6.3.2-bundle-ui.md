# 6.3.2 : bloc d'interface séparé (performance)

Type : refactoring (performance)
Statut : livré (branche `claude/hiver-k-s`)
Proposition : aucune (technique) ; lot S de `docs/proposals/feuille-de-route-2026-hiver.md`, constat P1

## Demande
> « le rendre performant »

## Diagnostic
Bloc d'entrée de 897 Ko (297 Ko gzip). Composition mesurée (modules rendus) : moteur `src/game` 596 Ko, composants 260 Ko,
UI tierce environ 400 Ko (Radix 160, Floating UI 72, tailwind-merge 72, sonner 34…). Le bloc d'entrée change à chaque déploiement :
tout est retéléchargé, UI tierce comprise.

## Ce qui change
- `vite.config.ts` : `manualChunks` en fonction ; Radix, Floating UI, tailwind-merge, sonner, react-remove-scroll et leurs dépendances
  vont dans un bloc `ui` (157 Ko, 51 Ko gzip), stable d'un déploiement à l'autre.
- Bloc d'entrée : **897 → 742 Ko** (297 → 245 Ko gzip).
- Joueur : rien de visible, sinon une mise à jour plus légère à recharger.

## Décisions et écarts
- Découpe du moteur par page **non faite** : `content.ts` et `flush.ts` agrègent tout le contenu (succès, saisons, Chroniques, passe…),
  donc tout le moteur est atteint dès l'entrée. Le séparer demande de rendre le contenu paresseux côté client : à proposer à part.
- `lucide-react` reste hors du bloc forcé : les icônes sont triées par page, un bloc forcé y mettrait celles des pages paresseuses.

## Invariants et tests
- Aucun changement de code applicatif. Build, tests et test de fumée du build (connexion, Unités, Ordres, Bâtiments) : mêmes résultats
  qu'avant (y compris 4 erreurs de synchronisation déjà présentes, dues aux navigations coupées du script).

## Design (DESIGN.md)
Sans objet.

## Docs mises à jour
Audit P1, feuille de route, GDD (journal), CLAUDE.md (règle sur `manualChunks`).

## Validation
`tsc -b`, `eslint src`, `vitest run`, `npm run build`, test de fumée du build local.

## Suites
Contenu paresseux côté client (succès, saisons, Chroniques chargés à la demande) pour sortir environ 150 Ko du moteur de l'entrée.
